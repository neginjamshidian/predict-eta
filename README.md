# predict-eta 🚚 (notebook-to-python refactor)

This project converts a Jupyter notebook (`FinalTransitTest.html`) into a modular, production-ready Python CLI app for **ETA (Estimated Time of Arrival) prediction** using machine learning models.

---

## 🧬 Project Structure

```
predict-eta/
├─ app/
│  ├─ main.py                # CLI entry point (train / predict)
│  ├─ algorithms/
│  │  ├─ linear_regression.py
│  │  ├─ random_forest.py
│  │  ├─ gradient_boosting.py
│  │  └─ decision_tree.py
│  └─ utils/
│     ├─ config.py
│     ├─ data_loading.py
│     ├─ preprocess.py
│     └─ metrics.py
├─ mock_data/
│  ├─ training.json          # Synthetic training data
│  └─ inference.json         # Synthetic test data
├─ models/                   # Saved models (*.pkl)
├─ requirements.txt          # Python dependencies
├─ run_app.bat               # Windows batch script for training & prediction
└─ .gitignore                # Ignore unnecessary files (env, cache, data)
```

---

## ⚙️ Setup & Run

### 1. Create a virtual environment

```bash
python -m venv .venv
.venv\Scripts\activate   # Windows
# source .venv/bin/activate   # macOS/Linux
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

### 3. Train & Predict (Windows)

You can use the automated batch script:

```bash
run_app.bat
```

Or run manually:

```bash
python -m app.main train --algo decision_tree --out models\dt.pkl
python -m app.main predict --model models\dt.pkl
```

Available algorithms:

* `linear_regression`
* `random_forest`
* `gradient_boosting`
* `decision_tree`

## 🧪 Mock Data

Synthetic JSON datasets are provided in `mock_data/`.
They simulate realistic columns:

* `weight_courier_raw`
* `travel_diff_times`
* `time_diff_label_till_shippingdate`
* `time_in_transit`

You can safely replace them with real data following the same schema.

## 🧼 Safety & Privacy

* All sensitive data and secrets have been **removed or redacted**.
* `.gitignore` excludes virtual environments, mock data, models, and system files.
* Real API keys or credentials should go in a `.env` file (never commit it).
